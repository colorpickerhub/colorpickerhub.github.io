Naming Colors in CSS

From color keywords to custom properties: how to name, organize and maintain colors in your stylesheets.

CSS color keywords

CSS includes about 148 named colors, from red and blue to rebeccapurple and papayawhip. Keywords are readable and quick for prototypes, but they are limited: you cannot adjust a keyword's lightness, and two keywords rarely match a brand palette. Use them for sketches and learning, then move to HEX or HSL values for real projects, where exact control matters.

HEX, RGB and HSL in stylesheets

HEX is the most common format in CSS because it is compact: color: #6C4CF1. RGB is useful when you need transparency with rgba(), and HSL is useful when you want to derive shades by changing lightness. Modern CSS also supports newer formats such as lab() and oklch(), which describe color more evenly, but HEX, RGB and HSL remain the safest choice for broad browser support today.

Custom properties are the real answer

The best way to name colors in CSS is with custom properties, also called CSS variables. Define them once at the root, such as --color-primary: #6C4CF1, and use var(--color-primary) everywhere. When the brand color changes, you update one line instead of hunting through hundreds of rules. Name variables by role, such as --color-button or --color-error, not by appearance, so a red that becomes orange does not leave you with a variable called --red that holds orange.

Organizing a color system

Group your variables by purpose: brand colors, neutrals, text colors, backgrounds, borders, and state colors for success, warning and error. Keep the list short, ideally under twenty variables, and document each one with a comment explaining where it is used. A small, documented system is easier to maintain than a large one, and it stops new colors creeping in with every feature.

Dark mode and theming with variables

Custom properties make theming easy: define a light set of values on :root and a dark set under a dark-mode class or media query, using the same variable names. The rest of your CSS does not change, because it reads the variables. This is the cleanest way to support dark mode, and it also makes seasonal themes or white-label versions possible with a single block of variable overrides.

Naming colors in design systems

Large design systems take color naming further, with tokens: abstract names such as color-surface, color-border and color-text-primary that describe a role rather than a value. The same token can hold a light value in one theme and a dark value in another, so the whole product can switch themes by changing the token values. This is how big products support dark mode, seasonal themes and white-label versions from a single codebase. Start with simple custom properties, and move to tokens when your product grows to several themes.

Migrating an old stylesheet

If your stylesheet already uses HEX codes scattered through hundreds of rules, migrate gradually: define custom properties for the most-used colors first, replace them rule by rule, and test after each batch. A gradual migration is safer than a single big change, and within a few weeks your stylesheet will be far easier to maintain.

Frequently asked questions

How many CSS named colors are there?

There are 148 named colors in CSS, including classics like red and newer additions like rebeccapurple.

Should I use color names or HEX codes?

Use HEX or HSL codes in production for exact control. Named colors are fine for prototypes and quick sketches.

What is the best way to organize colors in CSS?

Use custom properties named by role, such as --color-primary, defined once at the root and reused everywhere.

What are design tokens?

Design tokens are named values for colors, spacing and type that describe a role, such as color-surface, so themes can change the value without changing the code.
